# faultseg — 乱序遥测故障片段提取后端

从乱序到达的遥测事件中按模式提取故障片段，并按水位（watermark）发布结果。
核心逻辑（校验、匹配、发布）全部手写，仅使用标准库 `json` 做编解码。

## 目录结构

```
main.py               # 入口：python3 main.py INPUT_JSON OUTPUT_JSON
faultseg/
  __init__.py
  errors.py           # InputError：携带错误 JSON 路径
  validate.py         # 输入校验 + 转为内部 IR（模式树 / 操作流）
  engine.py           # 匹配引擎：叶/or/seq/rep、否定事件、span 裁剪、水位发布
  pipeline.py         # 解析 → 校验 → 执行 的整次流水线
tests/
  brute_force.py      # 独立枚举参考实现（与引擎零共享代码）
  acceptance.py       # 独立枚举验收：定向 + 随机差分 + 模糊 + 文件行为
```

## 运行

```bash
python3 main.py INPUT_JSON OUTPUT_JSON
```

* 成功：输出 JSON 数组**原子替换** `OUTPUT_JSON`，退出码 0；
* 输入非法（结构、类型、重复、未知成员任一）：整次拒绝，向 stderr
  打印一个错误 JSON 路径（零基下标，如 `$.ops[2][3]`；JSON 语法错打印
  `$`），**保留旧输出文件不动**，退出码 1；
* 输入文件不可读 / 输出不可写：退出码 2。

## 输入格式

顶层对象仅含三个成员，缺一不可，出现未知成员即整次拒绝：

* `span`：正整数秒（布尔不是整数）；
* `pattern`：模式，递归定义——
  * 叶：类型字符串（非空 ASCII 字母数字串）；
  * `["or", P, Q]`：并集；
  * `["seq", P, Q, g, b]`：顺序连接；
  * `["rep", P, m, n, g, b]`：m 至 n 次重复（m、n 为正整数且 m ≤ n）；
  * `g = [lo, hi]`：非负整数闭区间（lo ≤ hi）；
  * `b`：无重复的类型数组（否定/恢复事件类型，可为空数组）；
* `ops`：操作数组，元素为——
  * 事件 `[id, key, type, t]`：`id/key/type` 均为非空 ASCII 字母数字串，
    `id` 全局唯一，`t` 为非负整数秒（禁布尔）；事件须满足 `t` 大于当前
    水位，否则整次拒绝；
  * 整数水位 `W`（禁布尔）：初始水位 -1，只能不减，否则整次拒绝；
    EOF 不推进水位。

## 匹配语义

* 叶取单事件；`or` 取两边并集；`seq`/`rep` 连接左右（相邻）匹配。
* 连接要求：同 key；按 `(t, id)` 严格递增（蕴含事件不复用）；左末到
  右首时间差落在闭区间 `g` 内；两时刻的**开区间**内不存在同 key 且类型
  属于 `b` 的任何**原始**事件（未选中的恢复事件同样否定片段）。其他事件
  可跳过。
* 只保留首末时间差 ≤ `span` 的匹配；相同 id 序列去重；重叠结果均保留。
* 首事件时刻为 `s` 的结果，仅在水位**首次达到或超过** `s + span` 时
  发布一次（此刻窗口 `[s, s+span]` 内的事件与否定事件均已到齐，结果
  集合已确定）。

## 输出格式

按水位操作排列的数组，每个水位操作对应一项（空批保留为 `[]`），项为
该水位新增匹配的数组。每个匹配为
`{"key": ..., "ids": [...], "start": ..., "end": ...}`，
批内按 `key` 再按 `ids` 的 ASCII 字典序排序。

示例（来自需求）：`span=5`、模式 `["seq","A","B",[0,5],["R"]]`，同 key
依次收 `a/A@0`、`b/B@4`、`r/R@2`，水位 5 —— `R@2` 落在开区间 `(0,4)`
内否定该片段，输出 `[[]]`。

## 验收测试

```bash
python3 tests/acceptance.py [NUM_RANDOM] [SEED]
```

* 定向用例：规范示例、g 边界、span 边界、同 t 按 id 排序、or 去重、
  rep 多重复、否定事件（窗内/边缘/窗外/异 key/未列出类型）、水位首次
  达到/不重复发布/空批/EOF 不推进、跨 key 不匹配、嵌套模式等，逐一
  对比手工计算结果（进程内 + CLI 双通道）；
* 非法用例：语法错（`$`）、未知成员、缺失成员、各类结构/类型/重复
  错误，逐一核对退出码、stderr 上的精确错误路径、旧输出文件保留；
* 随机差分：`tests/brute_force.py` 对每个 key 枚举全部事件子序列并按
  形式语义独立判定，与引擎输出逐批比对，并校验发布时刻、排序、去重、
  `(t,id)` 递增等不变式；
* 模糊测试：随机/变异文档，要求要么以 `$` 开头的路径干净拒绝且文件
  不动，要么（若合法）与暴力枚举一致；
* 文件行为与中等规模冒烟（3000 叶匹配、100×100 共 10000 条 seq 匹配）。
